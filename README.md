# SEDAR · Seismic Response Lab

A frontend-only React, Tailwind CSS and Vite demonstration for the SEDAR college prototype.

## Run locally

```sh
npm install
npm run dev
```

`npm run build` produces the static website in `dist`. `npm test` checks the spring model, damping direction, boundedness, settling, and passive comparison.

## Experiment

Click the building or Trigger earthquake for a six-second ground excitation. Adjust intensity, toggle active damping, pause/resume, reset, or enable phone motion. Four corner springs, seated over screws fixed to the base with 1/2 inch (12.7 mm) insertion into each longer spring, support the moving platform. Two compact base-mounted push-pull solenoids sit between S1/S2 and S3/S4, centered between closer spring pairs with slightly longer illustrated plungers. Short plungers shift from the inward side at rest toward the spring-facing side when energized; the units are mirrored, and no rod spans a spring pair. They act on spring-contact collars, not directly on the building. Brackets and collars are proposed visualization details; the owner specified four longer springs and a 1/2-inch screw insertion depth. The sensor is represented on the roof. The system tab includes the supplied wiring diagram.

Phone motion requires HTTPS or localhost and a browser/device with DeviceMotion support. iOS requires permission from the button gesture. Real device testing is needed to confirm sensor availability on a particular phone. Desktop controls always remain available.

## Model and reference choices

The simulation uses a unit-mass spring system with a fixed 120 Hz integration step. Base displacement excites the building through springs and passive damping. The ideal controller applies capped force opposite building velocity. A second passive model receives the same base input; the displayed reduction compares RMS displacements accumulated since the latest triggered quake (or reset). Displacement uses illustrative units, not calibrated millimetres or acceleration measurements. Intensity is not a Richter magnitude. Turning damping on or off mid-event affects the accumulated comparison.

The force model is an idealization of the proposed actuator feedback; it does not simulate physical relay delay, contact wear, solenoid stroke, contact geometry, heating, coil dynamics or a validated hardware control law. Roof motion sensing supports visualization but is not a prescription for real structural safety. The spring/actuator geometry is conceptual and requires mechanical validation.

The detailed project description and supplied circuit use an Arduino Nano, MPU6050, LM2596, two-channel relay and two 12 V solenoids with flyback diodes. Those are the reference for this app. The supplied PDF is retained as a reference but describes an earlier MOSFET/eddy-current design. True eddy-current damping requires a moving conductor and magnetic field; this frontend illustrates active solenoid response.

## Revision 02 / 3D inspection

The Three.js model supports free orbit, zoom and pan, five camera presets, a mechanism-only view, and independent reference auto-rotation. Camera freedom does not imply three-axis physical control. The website PDF is a expanded reference with a 20-step assembly, wiring and commissioning guide, generated by `scripts/build_reference.py`.
